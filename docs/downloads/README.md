Every file here is generated by this repository's own code (`scripts/`), passes the on-disk
format validator (single band, float32, values in **[0, 1]**, EPSG:32611, matching shape and
geotransform of `sample_submission.tif`), and has an adjacent `.json` receipt where one was
written by its run, carrying sha256, submission name and note (≤140 chars each). Whether a
given file is **OK to submit** is stated on the front page next to its download button — it
is never implied.

Rules before a file is added here:

1. Generated by our own code, from data we are entitled to use (free, official, publicly
   verifiable sources; see the [sources page](../sources.html)).
2. Must pass the on-disk validator (see [Make a submission](../executive-summary.html)).
   Receipt attached.
3. Uniqueness-screened against the sibling registry (`evidence/registry_screen_v2*.json`,
   `evidence/lane_gate_discovery_v2.json`); the literal lane rule and the coverage-adjusted
   policy verdict are both published.
4. Name and note follow the submission rules (each ≤140 characters).
5. sha256 listed in the run card (`evidence/run_card_discovery_v1.json`).

*Note:* `*.tif` files are git-ignored by default; `docs/downloads/*.tif` is explicitly
re-included in `.gitignore`, so published deliverables do enter Git on purpose while raw
inputs never do.
