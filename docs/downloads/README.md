**"Download: yes" means format-valid, not recommended.** Each `.tif` is float32, one band, EPSG:32611, the organizer grid
(3292 × 3730, 100 m, origin 243350 / 4508550), values in {0, 1}, validated after writing. The `.zip` beside each
holds the same single GeoTIFF.

Why not submit: the shared uniqueness gate reports a proximity duplicate (dots within 3 px of dense registry layers on
263 of 944 priors for the primary), and the measurement itself is negative. Full verdicts: [the executive summary](../executive-summary.html),
[the run card](../../evidence/run_card.json), [leader analysis](../research/leader-analysis-2026-10-09.md).

Hashes, validator output and the note text are in the JSON receipts next to each file.

Rules before a file is added here:

1. It must be generated by our own code, from inputs we are entitled to use (see the [summary](../executive-summary.html)).
2. It must pass `validate_submission` (see [How to submit](../submit.html)). Attach the receipt JSON.
3. Its uniqueness gate result must be recorded in the receipt, including failures.
4. Its name and note must follow [How to submit](../submit.html#limits) (note ≤ 140 characters).
5. Its SHA-256 must be listed in `evidence/run_card.json`.

*Note:* `*.tif` files are git-ignored, so adding a file here requires an explicit `git add -f`. The two files above were added that way.
