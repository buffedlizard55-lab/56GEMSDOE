Five steps, one download
  1. Open the evidence page and pick a card. Both files are validated: single-band float32, EPSG:32611, 100 m, 3730 × 3292, values in [0, 1], no NaN, no nodata tag.
  2. Click Download .tif (or the .zip - the portal takes either; the .zip holds exactly one GeoTIFF).
  3. On the competition's "New submission" form, attach the file. Leave nothing else changed: the form checks CRS, shape and geotransform against the sample submission, and it requires every predicted value to lie in [0, 1].
  4. Paste the note from the card (≤140 characters, already written for you) so the submission is identifiable later, and submit. Weekly slots are limited and shared - see the submission limits on the competition rules page - so file the one raster you would defend.
  5. Keep the receipt. The file's sha256 is on the card; if the portal score ever differs from what this page claims, the sha256 is what settles it.
What you are buying, stated plainly

Both files are legal submissions, and neither is cleared for a slot by our instruments: on the shared blocked holdout our best arm reaches 0.0383 where the group's incumbent raster reaches 0.0900 on the identical folds, and that same instrument is provably inverted for the near-catalogue pruning question (IR-56-011). A slot is worth spending only if you want an orthogonal bet - a purely magnetic-gradient, model-free emission - against the DEM-scarp family that everything else in this group has filed. The one-click file is here either way, because the deliverable of this project is a submission that can be filed, plus the receipts that say what it is worth.

The two failure modes that produce "Predicted values must be in range [0, 1]"

  • The float32 sentinel. training_features.tif stores nodata as -3.4028234663852886e+38; any pipeline that reads a band and writes predictions without replacing it ships values outside [0,1]. Our loader asserts band identity and maps the sentinel to NaN before anything else (src/gems56/corrections.py:load_fields).
  • The nodata tag itself. A raster tagged nodata=-3.4e38 can be rejected even where its cells are legal. Our writer sets nodata=None and fills outside-footprint cells with 0.0, then the build re-opens the file and reports min, max, NaN count and the tag in docs/downloads/checks-*.json.
