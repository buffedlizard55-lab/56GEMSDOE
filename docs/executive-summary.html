The two failure modes that produce "Predicted values must be in range [0, 1]"

  • The float32 sentinel. training_features.tif stores nodata as -3.4028234663852886e+38; any pipeline that reads a band and writes predictions without replacing it ships values outside [0,1]. Our loader asserts band identity and maps the sentinel to NaN before anything else (src/gems56/corrections.py:load_fields).
  • The nodata tag itself. A raster tagged nodata=-3.4e38 can be rejected even where its cells are legal. Our writer sets nodata=None and fills outside-footprint cells with 0.0, then the build re-opens the file and reports min, max, NaN count and the tag in docs/downloads/checks-*.json.
