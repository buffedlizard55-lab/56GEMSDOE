How to submit (step by step)

This page explains the procedure. When a validated file exists it will be linked from the summary at the top.

The procedure

  1. Register and accept the rules on the competition page. Accepting the rules creates a binding agreement with DOE (rules, "Accept" on the DrivenData platform).
  2. Check the data terms before you download the training files. The data page requires login; its terms are not covered by the official rules.
  3. Generate the GeoTIFF from your own model, on the grid of training_features.tif (EPSG:32611, 100 m). Write NaN outside the footprint and probabilities in [0, 1] inside it.
  4. Validate the file. The validator in this repository rejects NaN outside a footprint, values outside [0, 1], a sentinel nodata value, a wrong CRS or grid, and multi-band files: 
    /home/user/.venv-gems/bin/python -c "import sys; sys.path.insert(0,'src'); from gems.submission import validate_submission; print(validate_submission('path/to/file.tif'))"
  5. Name and comment. Give the file a unique name and a one-line comment, for example clustering with k=25. Do not reuse another team's name or file.
  6. Upload on the DrivenData submission page. Record the returned receipt; a score shown there is an ORGANIZER-CONFIRMED value.
  7. Disclose generative-AI use in the narrative (rules §3.2). Keep public elements free of trade secrets (rules A.4).

"Predicted values must be in range [0, 1]"

The portal rejects the file when any finite cell is outside [0, 1]. Causes, in order of likelihood:

  1. Unclipped model output (negatives or values above 1). Fix: clip, or apply a sigmoid.
  2. A nodata sentinel inside the footprint, for example -3.4028234663852886e+38. The owner's site attributes the error to this (CLAIM, not verified here: IR-06). Fix: replace it with NaN, and check the nodata tag.
  3. NaN or wrong grid, for example a different transform, size or CRS. Fix: write on the reference grid.

Run the validator above before every upload.
